# AutoVeo

사진과 영상이 담긴 폴더 하나를 고르면, 사진을 작은 그룹으로 묶어 그룹마다 영상 클립을 만들고,
AI가 클립을 평가해 쓸 만한 것을 추천하고, 그 클립들로 타임라인과 자막을 만든 뒤 배경음악을
얹어 한 편의 영상으로 완성하는 데스크톱 웹앱입니다.

- 사진과 영상은 외부 서버에 올라가지 않습니다. 모든 처리는 이 컴퓨터에서 일어납니다.
- 원본 파일은 읽기만 하고 절대 수정하지 않습니다.

## 파이프라인

```text
1. 소스      폴더 스캔 → 미리보기·썸네일 생성 → 사진 품질 확인
2. 그룹      사진을 2~5장씩 묶고(직접 고침) 움직임을 고른 뒤 그룹마다 mp4 클립을 생성
3. 영상      촬영 영상에서 좋은 구간을 자동으로 찾고, 고른 구간만 잘라 mp4 클립으로 제작
4. 클립      두 종류의 클립을 AI가 평가 → 점수·설명·자막 초안 → 사용할 클립과 색감 필터 선택
5. 타임라인  선택한 클립의 순서와 자막을 정하고 프레임 단위 타임라인을 계산
6. 완성      배경음악 선택 → 무음 렌더 → 음악 합성 → 자동 검증 → MP4
```

사진으로 만든 클립과 영상에서 잘라 낸 클립은 같은 규격(해상도·FPS)의 mp4가 되므로,
타임라인에서 완전히 똑같이 다뤄집니다.

각 단계는 화면 위쪽 탭에 그대로 대응하고, 단계마다 버튼 하나로 실행합니다. 같은 입력으로 다시
실행하면 캐시를 재사용하므로 앞 단계를 다시 계산하지 않습니다.

## 처음 실행하기

```powershell
pnpm install
pnpm dev
```

다음 문장이 나오면 <http://127.0.0.1:5173> 을 엽니다.

```text
Server listening at http://127.0.0.1:5178
Local: http://127.0.0.1:5173/
```

이 PowerShell 창을 닫으면 서버도 함께 종료됩니다.

## 화면별 사용법

### 1단계 — 소스

1. 영상 제목을 입력하고 **찾아보기**로 사진·영상 폴더를 고릅니다. 경로를 직접 붙여 넣어도
   됩니다. (예: `D:\Travel\Jeju-2026`)

   폴더 선택 창은 탐색기와 같은 모양으로 열리고, 브라우저 창 앞에 나타나며, AutoVeo가 설치된
   폴더에서 시작합니다.

2. **프로젝트 시작** → **원본 불러오기**를 누릅니다.
3. 스캔·미리보기 생성·품질 확인이 한 번에 이어서 실행됩니다.
4. 격자에서 사진을 클릭하면 그 사진을 제외하거나 되돌립니다.

읽어 들이는 정보는 촬영 시각, 방향, 크기, 흔들림·유사 사진 여부뿐입니다. 원본에는 아무것도
쓰지 않습니다.

### 2단계 — 그룹

1. 화면 비율·해상도·초당 프레임을 고릅니다. 이 값은 클립과 최종 영상 모두에 적용됩니다.
2. **그룹 클립 만들기**를 누릅니다.

그룹은 다음 기준으로 자동으로 나뉩니다.

- 촬영 간격 8분 이상이면 다른 그룹
- 날짜가 바뀌면 다른 그룹
- GPS 기준 800m 이상 이동했으면 다른 그룹
- 한 그룹은 최대 5장

제외한 사진, 흔들린 사진, 유사 사진 묶음의 비대표 컷은 그룹에 들어가지 않습니다.

자동으로 묶은 결과가 마음에 들지 않으면 직접 고칠 수 있습니다.

- 사진을 클릭해 고른 뒤 **◀ 앞 그룹 / 뒤 그룹 ▶** 으로 다른 그룹에 옮깁니다. 양 끝에서 더
  밀면 새 그룹이 생깁니다.
- **여기서 나누기** 는 고른 사진을 기준으로 그룹을 둘로 가릅니다.
- **클립에서 제외** 는 고른 사진을 그룹에서 빼냅니다. 그 사진은 클립에 들어가지 않고 아래
  **그룹에 없는 사진** 목록으로 내려가며, 거기서 다시 넣을 수 있습니다.
- 한 그룹에는 사진을 최대 6장까지 넣을 수 있습니다.

한 번이라도 직접 고치면 그 구성이 저장되고, 이후 자동 묶기가 덮어쓰지 않습니다.
**자동으로 되돌리기** 를 누르면 다시 자동 규칙을 따릅니다.

#### 클립 움직임 고르기

그룹마다 **움직임**을 세 가지 중에서 고릅니다. 사진이 같아도 전혀 다른 느낌이 됩니다.

| 옵션           | 사진 한 장 | 겹침  | 움직임                                          |
| -------------- | ---------- | ----- | ----------------------------------------------- |
| **차분하게**   | 3.4초      | 0.9초 | 거의 정지. 아주 느리게 밀고 당기기만 합니다     |
| **기본**       | 2.6초      | 0.5초 | 사진마다 방향을 바꿔 천천히 움직입니다          |
| **역동적으로** | 1.9초      | 0.3초 | 크게 확대하고 대각선으로 움직이며 살짝 기웁니다 |

움직임을 바꾼 뒤 **이 클립만 다시 만들기**를 누르면 그 그룹의 클립 하나만 다시 만듭니다.
나머지 클립은 그대로 두므로 전체를 기다릴 필요가 없습니다. 위쪽 **클립 다시 만들기**는 바뀐
그룹만 골라 다시 만들고 나머지는 이미 만든 파일을 재사용합니다.

클립은 Remotion으로 렌더합니다. ffmpeg만으로는 어려운 회전·대각선 이동까지 쓸 수 있어 세
옵션의 차이가 분명하게 드러납니다. Remotion 렌더에 실패하면 ffmpeg 방식으로 자동 대체하며, 이
경우 길이는 옵션대로 나오지만 회전은 빠집니다. ComfyUI를 연결해 두었고 Remotion을 쓸 수 없는
환경이라면 이미지→영상 워크플로로 만듭니다.

### 3단계 — 영상

촬영 영상이 있으면 이 단계에서 클립으로 바꿉니다. 영상이 없는 폴더라면 그냥 지나가면 됩니다.

1. **좋은 구간 찾기** — 영상마다 움직임 변화로 후보 구간을 만들고, 밝기·선명도·흔들림을 재서
   점수를 매깁니다. 겹치지 않는 상위 구간만 남기고 그중 3개를 미리 선택해 둡니다. 이 단계는
   파일을 만들지 않습니다. 화면에서 확인하는 용도입니다.
2. 구간을 확인하고 고칩니다.
   - 썸네일의 **▶ 미리보기**를 누르면 그 구간만 재생됩니다. 아직 클립을 만들기 전에는 원본
     미리보기에서 시작 지점으로 건너뛰어 재생하고 끝 지점에서 멈춥니다. 클립을 만든 뒤에는
     잘라 낸 파일을 그대로 재생합니다.
   - **넣기 / 빼기**로 클립으로 만들 구간을 정합니다.
   - 시작·끝의 **− / +** 로 0.5초씩 구간을 조절합니다. (2~20초) 구간을 조절하면 미리보기도
     새 범위로 다시 열립니다.
   - **구간 직접 추가**로 자동 탐지가 놓친 곳을 넣습니다.
   - 막대 그래프에서 각 구간이 영상 어디쯤인지 볼 수 있습니다.
3. **선택 구간을 클립으로** — 고른 구간만 출력 규격에 맞춰 실제 mp4로 잘라 냅니다.

구간을 옮기면 그 구간의 클립은 다시 만들고, 건드리지 않은 구간은 이미 만든 파일을
재사용합니다.

### 4단계 — 클립

**AI로 클립 분석**을 누르면 각 클립의 대표 프레임을 뽑아 평가합니다. 사진 그룹 클립과 영상에서
잘라 낸 클립을 똑같은 방식으로 봅니다.

각 클립에는 점수(0~100), 분류, 한국어 설명, 자막 초안이 붙습니다.

분석이 끝나면 **AI가 쓸 만한 클립을 미리 골라 둡니다.** 72점 이상인 클립이 '넣기' 상태가 되고
나머지는 빠집니다. 모든 클립의 점수가 낮으면 영상이 비지 않도록 상위 3개는 남깁니다. 추천이
마음에 들지 않으면 **넣기 / 빼기**로 바꾸면 되고, 한 번 직접 바꾼 클립은 다시 분석해도 그
결정을 유지합니다.

#### 색감 필터

**원본(원) · 화사하게(화) · 따뜻하게(따) · 시원하게(시) · 모노톤(모) · 필름(필)** 중에서
고릅니다. 위쪽 색감 필터 패널에서 고르면 모든 클립에 한 번에 적용되고, 클립 카드 아래의 작은
동그라미로는 그 클립만 바꿉니다. 동그라미에는 한글 첫 글자가 적혀 있어 구분할 수 있고,
썸네일에 같은 필터가 걸려 결과를 바로 확인할 수 있습니다.

필터는 최종 렌더에서 한 번만 입혀집니다. 클립 파일 자체는 그대로이므로 필터를 바꿔도 클립을
다시 만들 필요가 없습니다.

Ollama 비전 모델이 없으면 화질·안정성·흔들림만으로 점수를 매기고 자막 초안은 만들지 않습니다.
파이프라인 자체는 그대로 끝까지 진행됩니다.

### 5단계 — 타임라인

1. 왼쪽 막대와 목록에서 순서를 바꾸거나(↑ ↓) 클립을 뺍니다(✕).
2. 클립을 고르고 오른쪽에서 자막을 쓴 뒤 **자막 저장**을 누릅니다.
3. **타임라인 만들기**를 누릅니다.

영상 길이는 선택한 클립 길이의 합으로 정해집니다. 프레임 계산은 초 단위 실수를 더하지 않고
선택한 FPS 기준 정수 프레임으로 합니다.

직접 저장한 자막은 `source: "user"`로 남아 다시 분석해도 덮어쓰지 않습니다. 자막을 넣어 둔
클립은 하나도 빠짐없이 화면에 올라갑니다. 자막을 줄이고 싶으면 그 클립의 자막을 비우면 됩니다.

자막은 한 줄 22자, 두 줄까지입니다. 이보다 길면 뒤가 잘리고 경고가 뜨므로 문장을 다듬으세요.

> 자막을 저장한 뒤에는 **타임라인 만들기**를 다시 누르고, 완성 단계에서 **무음 영상 만들기**도
> 다시 실행해야 영상에 반영됩니다. 앞 단계를 고치면 뒤 단계는 자동으로 무효가 됩니다.

### 6단계 — 완성

1. **자동 추천 / 직접 선택 / 음악 없음** 중 하나를 고르고 **이 설정으로 음악 넣기**를 누릅니다.
2. **1. 무음 영상 만들기** → 미리보기로 순서와 자막을 확인합니다.
3. **2. 음악 합쳐 완성** → 자동 검증 결과와 최종 영상을 확인하고 **MP4 다운로드**를 누릅니다.

두 번째 작업은 H.264 비디오를 다시 인코딩하지 않고 그대로 복사하므로, 음악만 바꿀 때는 무음
영상을 다시 만들 필요가 없습니다.

자동 검증 항목:

- 무음 영상과 최종 영상의 길이 차이가 0.1초 이하인가
- 비디오가 재인코딩 없이 복사되었는가
- 검은 화면이 전체의 5% 미만인가
- 음악을 넣은 영상이 전 구간 무음이 아닌가
- 최종 음량이 −16 LUFS 목표 범위인가
- 고르게 뽑은 10개 프레임의 밝기가 정상인가

하나라도 실패하면 완성으로 표시하지 않습니다. 음악을 쓰지 않은 경우 무음·음량 검사는 **해당
없음**으로 표시됩니다.

## 배경음악 등록

음악은 이 프로젝트의 `music/` 폴더에서만 읽습니다.

1. 사용 허가를 받은 MP3를 분위기 폴더에 넣습니다.
   `music/calm/`, `music/night/`, `music/upbeat/`, `music/emotional/`
2. `config/music/tracks.json`에 등록합니다.

```json
{
  "schemaVersion": 2,
  "tracks": [
    {
      "id": "my-calm-track",
      "path": "calm/my-calm-track.mp3",
      "mood": ["calm", "acoustic"],
      "energy": 0.35,
      "tags": ["travel"],
      "license": "직접 구매한 라이선스",
      "attribution": "아티스트 이름",
      "bpm": null
    }
  ]
}
```

`path`는 `music/` 기준 상대 경로입니다. `license`와 `attribution`은 앱이 추측하지 않으므로
사실대로 적어야 합니다. MP3 길이는 입력값을 믿지 않고 ffprobe로 직접 측정합니다.

짧은 영상에서 곡이 자주 바뀌지 않도록 3분 미만은 1곡, 3~6분은 최대 2곡, 6분 초과는 3분마다
1곡(최대 4곡)으로 제한합니다.

## 설정 (선택)

화면 오른쪽 위 **설정**에서 로컬 도구를 연결합니다. 셋 다 없어도 파이프라인은 끝까지 돕니다.

### Ollama 비전 모델

클립 점수·설명·자막 초안을 만듭니다.

```powershell
irm https://ollama.com/install.ps1 | iex
ollama pull qwen3-vl:4b
```

`.env`에 주소를 넣고 서버를 다시 시작합니다.

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
```

설정 화면에서 사용할 모델을 고릅니다. 8GB VRAM 기준 실측 결과는 다음과 같습니다.

| 모델          | VRAM  | GPU 배치           | 클립당 | 설명 품질                        |
| ------------- | ----- | ------------------ | ------ | -------------------------------- |
| `qwen3-vl:8b` | 6.9GB | 78% GPU (일부 CPU) | 3~5초  | 같은 장면을 일관되게 설명 (권장) |
| `qwen3-vl:4b` | 4.2GB | 100% GPU           | 1초    | 빠르지만 사물 식별이 흔들림      |

비전(vision) 기능이 없는 모델은 목록에 있어도 사용되지 않습니다.

대표 프레임은 모델에 보내기 전에 가로 768px로 줄입니다. 원본 크기로 보내면 1080p는 4,103토큰,
4K는 8,183토큰이 되어 Ollama 기본 컨텍스트(4,096)를 넘겨 분석이 조용히 실패합니다. 768px로
줄이면 3장을 합쳐도 약 2,100토큰이라 기본 설정에서 안전하고, 판단 품질은 떨어지지 않습니다.

### ComfyUI

그룹 클립을 이미지→영상 워크플로로 만듭니다. 연결하지 않거나 실패하면 기본 클립 생성으로
자동 대체됩니다. ComfyUI에서 검증한 워크플로를 **Save (API Format)**으로 내보내고 설정 화면에
주소와 경로를 저장합니다. 보안을 위해 `localhost`, `127.0.0.1`, `::1`만 허용합니다.

워크플로에는 `{{INPUT_IMAGE}}`, `{{PROMPT}}`, `{{TARGET_FRAMES}}`, `{{OUTPUT_PREFIX}}`가 반드시
있어야 합니다. 전체 계약은 [`config/comfy/README.md`](config/comfy/README.md)에 있습니다.

### FFmpeg

번들된 실행 파일을 자동으로 씁니다. 직접 지정하려면 `.env`에 넣습니다.

```dotenv
FFMPEG_PATH=C:\path\to\ffmpeg.exe
FFPROBE_PATH=C:\path\to\ffprobe.exe
REMOTION_BROWSER_EXECUTABLE=C:\Program Files\Google\Chrome\Application\chrome.exe
```

## 파일이 저장되는 위치

| 위치                             | 내용                                       |
| -------------------------------- | ------------------------------------------ |
| 원본 폴더                        | 읽기 전용. 앱이 수정하지 않음              |
| `data/app.db`                    | 프로젝트, 설정, 단계 진행 상태와 캐시      |
| `work/thumbs/`, `work/analysis/` | 화면용 썸네일과 분석 이미지                |
| `work/proxies/`                  | 영상 미리보기·분석용 프록시                |
| `work/render-assets/`            | 렌더용 고화질 사진과 출력 해상도 영상      |
| `work/clips/`                    | 그룹 클립·영상에서 잘라 낸 클립과 썸네일   |
| `work/manifests/`                | 스캔·그룹·영상 구간·클립·자막·구성 JSON    |
| `work/plans/`                    | 프레임 단위 렌더 타임라인                  |
| `work/intermediate/`             | 프로젝트별 무음 H.264 영상                 |
| `output/<프로젝트 ID>/movie.mp4` | 검증을 통과한 최종 영상                    |
| `music/`, `config/music/`        | 사용자가 등록한 읽기 전용 MP3와 메타데이터 |

`data/`와 `work/`를 지워도 원본 사진은 지워지지 않지만 진행 상태와 분석 결과는 초기화됩니다.
지우기 전에 `pnpm dev`를 반드시 종료하세요.

## 자주 생기는 문제

**“원격 서버에 연결할 수 없습니다”** — `pnpm dev`가 실행 중인지 확인하고 페이지를 새로
고칩니다.

**“폴더를 찾을 수 없거나 읽을 수 없습니다”** — 전체 경로인지, 따옴표가 붙지 않았는지, 파일이
아니라 폴더 경로인지 확인합니다.

**pnpm이 `node_modules` 삭제를 물어보며 멈춤** — 프로젝트 폴더를 옮기면 생깁니다.
`pnpm install`을 한 번 다시 실행하세요.

**렌더가 오래 걸립니다** — 첫 **무음 영상 만들기**가 가장 오래 걸립니다. 4K·긴 영상·많은 컷은
더 오래 걸립니다. 음악만 바꿨다면 무음 렌더를 다시 하지 말고 음악 합성만 실행하세요.
