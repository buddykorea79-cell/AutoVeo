# 파이프라인 통합 검증

새 5단계 파이프라인을 실제 사진과 실제 드론 영상으로 처음부터 끝까지 돌리고, 결과 mp4를
ffprobe로 확인한 기록입니다.

## 검증 환경

| 항목     | 값                                               |
| -------- | ------------------------------------------------ |
| OS       | Windows 11 Pro 26200                             |
| Node     | 24.19.0                                          |
| pnpm     | 11.19.0                                          |
| FFmpeg   | `ffmpeg-ffprobe-static` 6.1.2-rc.1 (번들)        |
| Remotion | 4.0.513                                          |
| Ollama   | `qwen3-vl:4b` (vision), `http://127.0.0.1:11434` |
| ComfyUI  | 연결하지 않음 (기본 클립 생성 경로 검증)         |

## 입력

- 사진 14장 (삼성 갤럭시 JPEG, 4000×3000 안팎)
- 드론 영상 1개: `DJI_20260724161254_0021_D.MP4`에서 20초 지점부터 40초를 스트림 복사한 것
  (HEVC, 3840×2160, 40.03초, 439MB)
- 출력 규격: 16:9 · 720p · 30fps

## 단계별 결과

| 단계          | 소요    | 결과                                                              |
| ------------- | ------- | ----------------------------------------------------------------- |
| import        | 0.4초¹  | 사진 14 · 영상 1 · 제외 0                                         |
| group-clips   | 6.5초   | 그룹 4개 (1·5·5·1장), 클립 4개 생성 (2.6s · 11.0s · 11.0s · 2.6s) |
| analyze-clips | 41.6초  | 클립 6개, 6개 모두 AI 평가·설명·자막 초안 생성                    |
| timeline      | 32.4초  | 씬 6개, 1596프레임 @30fps = 53.20초, 1280×720, 경고 없음          |
| music         | 0.4초   | 등록된 MP3가 없어 트랙 없음으로 진행                              |

¹ 앞선 실행에서 만든 썸네일·프록시 캐시를 재사용했습니다. 캐시가 없으면 몇 분 걸립니다.

## ffprobe 확인

### 생성한 그룹 클립

```text
work/clips/<프로젝트 ID>/g_0d59870db9-adb06f67.mp4   1280x720  78프레임   2.600000초
work/clips/<프로젝트 ID>/g_b5c2fe78c6-db479f69.mp4   1280x720  330프레임  11.000000초
work/clips/<프로젝트 ID>/g_ba777d41cc-5864cba9.mp4   1280x720  330프레임  11.000000초
work/clips/<프로젝트 ID>/g_fc2f251c32-0eec3849.mp4   1280x720  78프레임   2.600000초
```

사진 1장은 78프레임(2.6초), 5장은 330프레임(5×78 − 4×15)으로 계산과 정확히 일치합니다.

### 최종 영상

```text
codec_name=h264
codec_type=video
width=1280
height=720
r_frame_rate=30/1
nb_frames=1596
duration=53.200000
```

렌더 계획의 `totalFrames=1596`, `fps=30`과 정확히 일치합니다.

### 자동 검증 리포트

```text
pass     duration: 무음 영상과 최종 영상의 길이가 같습니다.
pass     video-copy: H.264 비디오를 다시 인코딩하지 않고 그대로 복사했습니다.
pass     blackdetect: 검은 구간이 전체의 5% 미만입니다.
skipped  silencedetect: 음악 없음과 모든 장면 음소거 설정에 따라 오디오 트랙을 넣지 않았습니다.
skipped  loudnorm: 오디오가 없어 라우드니스 측정을 건너뛰었습니다.
pass     brightness-samples: 고르게 뽑은 10프레임의 밝기가 정상입니다.
```

`silencedetect`와 `loudnorm`은 등록된 MP3가 없어 오디오 트랙을 만들지 않았기 때문에 건너뛴
것이며, 실패가 아닙니다.

### 프레임 육안 확인

최종 영상의 45 · 200 · 700 · 1100 · 1500번째 프레임을 뽑아 확인했습니다. 그룹 클립의 카메라
움직임, 컷 사이 교차 전환, 한국어 자막(`수면 위의 현대 건축물`), 드론 영상 구간이 모두 정상
출력되었습니다.

## 검증 중에 발견해 고친 문제

1. **생성한 그룹 클립이 단계 성공 직후 삭제됨** — `context.trackPartialOutput`은 단계가 끝나면
   성공 여부와 관계없이 등록된 키를 지웁니다. 최종 산출물인 클립을 여기에 등록하고 있었습니다.
   등록을 제거하고, 이 동작을 고정하는 회귀 테스트를 추가했습니다.
2. **렌더가 `clips/` 에셋을 거부** — 영상 씬의 에셋 키를 `proxies/`, `generated/`만 허용하고
   있었습니다. 허용 목록에 `render-assets/`, `clips/`를 추가했습니다.
3. **Remotion 번들이 Windows에서 EPERM으로 실패** — 폴더 심볼릭 링크는 관리자 권한이 필요합니다.
   번들 public 폴더에 이번 렌더가 쓰는 파일만 하드링크(실패 시 복사)로 심고
   `symlinkPublicDir: false`로 바꿨습니다.
4. **4K 원본에서 프레임을 반복 추출해 분석이 매우 느림** — 시간축이 같은 1280px 프록시로
   분석하도록 바꿔 영상 분석 시간이 수 분에서 41.6초로 줄었습니다.
5. **영상이 항상 720p 프록시로 렌더됨** — 렌더 단계의 영상 에셋을 출력 해상도에 맞춰 다시
   인코딩하도록 바꿨습니다(`render-assets/<id>.mp4`, CRF 20).
6. **`node_modules`가 옛 폴더 경로를 가리켜 모든 pnpm 명령이 멈춤** — 프로젝트를 다른 폴더로
   옮긴 흔적입니다. `pnpm install`로 다시 연결했습니다.

## 재현 방법

```powershell
pnpm install
pnpm dev
```

브라우저에서 소스 폴더를 고르고 1단계부터 5단계까지 순서대로 버튼을 누르면 같은 결과가
나옵니다. 결과 파일은 `output/<프로젝트 ID>/movie.mp4`입니다.
